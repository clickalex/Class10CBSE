Written questions · Write

SHORTS12 marks

1. What is a one-to-many relationship? Give an example.

Show Answer

Ans:

One record in table A matches many in table B. One student, many library issues. The Issue table stores AdmNo as FK.

SHORTS22 marks

2. What is referential integrity?

Show Answer

Ans:

A rule that every foreign-key value must match an existing primary key, so you cannot create orphan records.

SHORTS32 marks

3. What is referential integrity and why is it useful?

Show Answer

Ans:

Referential integrity is the rule that every value of a foreign key must match a value of the primary key in the related table, or be empty. It prevents ‘orphan' records — for example, a fee record belonging to a student who is not in the student table — and keeps the database reliable.

SHORTS42 marks

4. What is a many-to-many relationship? Explain why it needs a junction table, with an example.

Show Answer

Ans:

Many-to-many means rows on both sides link to many rows on the other — for example, each student borrows many books and each book is borrowed by many students. Neither table can hold the other's key directly, so a junction table (Issue: IssueID, RollNo, BookID, Date) stores each pairing as its own record.

APPLICATIONA53 marks

5. A shop has Customer and Order tables. Where does CustomerID go, and what relationship is this?

Show Answer

Ans:

CustomerID is PK in Customer and FK in Order. One-to-many (one customer, many orders).

APPLICATIONA63 marks

6. Riya is revising “Relationships and Multiple Tables” (One-to-one, one-to-many, many-to-many; referential integrity.). A classmate lost marks by doing this: Drawing the relationship backwards (PK on the many side). Apply the correct method and rewrite the scoring answer.

Show Answer

Ans:

Correct method: FK type must match PK type (both Integer, or both VARCHAR).
Why the mistake costs marks: Drawing the relationship backwards (PK on the many side).
Write the definition or formula first, then the working or example.

SHORTS73 marks

7. Explain the three types of relationship with an example of each.

Show Answer

Ans:

One-to-one: one record in the first table matches one in the second, for example one student and one library card.
One-to-many: one record in the first table matches many in the second, for example one class has many students.
Many-to-many: records on both sides match many on the other, for example students and subjects; this is usually split into two one-to-many relationships through a third table.

SHORTS83 marks

8. What is ‘cascade delete’? Describe one situation where it is useful and one where it is dangerous.

Show Answer

Ans:

Cascade delete automatically deletes child records when their parent is deleted.
Useful — removing a passed-out batch's students together with their old fee rows in one step.
Dangerous — deleting one supplier and silently wiping years of purchase history that accounts still needs. Prefer blocking the delete (referential integrity) unless you are certain the children are disposable.

LONGL94 marks

9. Explain how to relate Student and Issue in Base.

Show Answer

Ans:

AdmNo PK in Student; AdmNo FK in Issue (same type). Tools → Relationships, drag PK to FK, enable referential integrity. Then an issue cannot use a missing admission number.

COMPETENCYC104 marks

10. Read and answer: Deleting student 12 failed because “existing related records”. (a) What rule is firing? (b) Two safe ways to proceed. (c) When would cascade delete be wrong?

Show Answer

Ans:

(a) Referential integrity — Issue rows still point to 12.
(b) Delete or reassign the issue rows first; or (if asked) enable cascade delete.
(c) When those issues are history you must keep — never cascade-delete library history by accident.

COMPETENCYC114 marks

11. Read and answer: A Class 10 student is preparing “Relationships and Multiple Tables”. Their note says: Why multiple tables: store each fact once. Student details in Student; issues in Issue; link by AdmNo. The chapter is described as: One-to-one, one-to-many, many-to-many; referential integrity.. (a) Name the key idea. (b) How is this usually asked in the paper? (c) State one mistake that would cost a mark.

Show Answer

Ans:

(a) One-to-one, one-to-many, many-to-many; referential integrity.
(b) Draw one-to-many (Student–Issue) with referential integrity.
(c) Drawing the relationship backwards (PK on the many side).

LONGL125 marks

12. Discuss “Relationships and Multiple Tables” in detail. Include the idea that carries marks, one worked example or answer frame, and why students lose marks.

Show Answer

Ans:

Why multiple tables: store each fact once. Student details in Student; issues in Issue; link by AdmNo.
Marks lens: Draw one-to-many (Student–Issue) with referential integrity.
Method / memory trick: FK type must match PK type (both Integer, or both VARCHAR).
Do not: Drawing the relationship backwards (PK on the many side).
