Chapter 15 · Relationships and Multiple Tables

🎯 Marks lens

Draw one-to-many (Student–Issue) with referential integrity.
Know why we split tables (normalisation in simple words).

📖 Deep concepts

1. Why multiple tables: store each fact once. Student details in Student; issues in Issue; link by AdmNo.
2. One-to-one: one passport per citizen. Rare in Class 10 practicals.
3. One-to-many: one student, many issue records. The many side holds the foreign key.
4. Many-to-many: students and activities — needs a third (junction) table.
5. Creating a relationship: Tools → Relationships → add tables → drag PK to FK → tick Referential integrity → optionally Cascade Update/Delete.
6. Referential integrity: you cannot type an Issue.AdmNo that does not exist in Student. You cannot delete a student who still has issue rows (unless cascade).
7. Cascade update/delete: changing/deleting the parent PK updates/deletes child rows. Use delete cascade only when the question asks.

🛠️ Method, step by step

  1. Create both tables; set PKs.
  2. On the many side, add the FK field with the same type as the PK.
  3. Tools → Relationships.
  4. Drag Student.AdmNo to Issue.AdmNo.
  5. Tick Referential integrity → OK.

🧠 Memory tricks

  • FK type must match PK type (both Integer, or both VARCHAR).
  • The crow’s-foot / many side is the table that repeats the key.

⚠️ Mistakes that cost marks

  • Drawing the relationship backwards (PK on the many side).
  • Different data types on PK and FK — Base refuses the link.

SHORTS12 marks

1. What is a one-to-many relationship? Give an example.

Show Answer

Ans:

One record in table A matches many in table B. One student, many library issues. The Issue table stores AdmNo as FK.

SHORTS22 marks

2. What is referential integrity?

Show Answer

Ans:

A rule that every foreign-key value must match an existing primary key, so you cannot create orphan records.

LONGL34 marks

3. Explain how to relate Student and Issue in Base.

Show Answer

Ans:

AdmNo PK in Student; AdmNo FK in Issue (same type). Tools → Relationships, drag PK to FK, enable referential integrity. Then an issue cannot use a missing admission number.

APPLICATIONA43 marks

4. A shop has Customer and Order tables. Where does CustomerID go, and what relationship is this?

Show Answer

Ans:

CustomerID is PK in Customer and FK in Order. One-to-many (one customer, many orders).

COMPETENCYC54 marks

5. Read and answer: Deleting student 12 failed because “existing related records”. (a) What rule is firing? (b) Two safe ways to proceed. (c) When would cascade delete be wrong?

Show Answer

Ans:

(a) Referential integrity — Issue rows still point to 12.
(b) Delete or reassign the issue rows first; or (if asked) enable cascade delete.
(c) When those issues are history you must keep — never cascade-delete library history by accident.
