Scope: everything in the repository on branch `arena/01a0fd23-class10cbse`
(base commit `f31fa3e`, the merge of PR #14): the folder scaffold, the site
generator and its content, the published `docs/`, the scripts, the tests, the
workflows and the documentation — plus the **direct-download feature** (previous-year

## Method

1. Ran every gate the repository already had: `scripts/check_all.sh` (folder
   tree, content JSON, build + internal link check, `docs/` drift, icons, offline
   tests) — all six passed at the start, 103 tests. The staged workflows are
   byte-identical to the installed ones in `.github/workflows/`.
2. Rebuilt the site into a scratch directory and diffed it against the committed
   `docs/` — identical, so the published folder was not stale.
3. Crawled all 496 published HTML files with independent checkers (not the
   build's own link check): duplicate ids, in-page and cross-page anchors, `src`
   targets, `<title>`/description uniqueness and escaping, tag balance, block
   elements inside `<p>`, `target="_blank"` without `rel`, untyped buttons,
   leaked template braces and Python reprs.
4. Rendered every one of the 21,532 strings in `site/content/` through
   `inline()` and checked the HTML for balance.
5. Content integrity across 175 chapters, 2,133 written Q&A and 1,426 MCQs:
   schema, MCQ option/answer consistency (Latin and Devanagari labels), answer-key
   letter distribution, duplicates, template frames, doubled punctuation.
6. Re-derived every number the READMEs quote from the content and the build.
7. Read the JavaScript's handling of URL parameters and `localStorage` for
   injection routes.

## Findings initially left open (resolved below after approval)

**A. The MCQ answer key is position-biased.** Across all 1,426 chapter MCQs the
correct option is (a) 435 times (30.5%), **(b) 789 (55.3%)**, (c) 186 (13.0%) and
**(d) only 16 (1.1%)**. By subject, (b) is right for 62% of Maths, 62% of Science,
71% of Social Science, 63% of IT and 54% of English; (d) is never right in IT or
English (0 of 162 and 1 of 256). A student who marks (b) throughout scores about
55%, and learns a habit the real paper punishes. The mock engine shuffles question
order but not option order, so the 1,197-question mock pools inherit the bias.
*Suggested fix:* a deterministic build-time option shuffle for "clean" four-option
MCQs, skipping any whose options refer to one another ("all of the above", "both
(a) and (b)") or whose explanation cites a letter, with the answer letter
recomputed and a test that the distribution stays within a band. It rewrites
~1,400 answer keys, so it should be reviewed rather than applied silently.

**B. 198 of the 2,133 written Q&A (9.3%) are template scaffolds** ("Riya is
revising “…” …", "Amit is given this exam-style task from “…” …"). 89 of them
merely re-quote another question of the same chapter ("Treat it as an application
question"), so the same question appears twice in the bank. The mock engine already
excludes templated MCQs (`mocktest.is_filler`); written Q&A are not filtered, and
the new downloads list them as the page does. *Suggested fix:* write real
Application/Competency questions for those chapters, or filter the frames the way
the MCQ filler is filtered.

**C. Informational.** Most non-chapter pages share one generic meta description
("… chapter notes, formulas, exam Q&A and revision"); `page()` now accepts a
`description`, used by the Downloads page. Both menu buttons use inline `onclick`,
which would block a strict Content-Security-Policy (GitHub Pages sets none). The
heaviest page, `hindi/question-bank.html`, is 669 KB raw and 77 KB gzipped.

How it avoids doing damage: the wrong options keep their relative order and only the
right one moves; **30 of the original MCQs with four sorted numbers** (years, marks,
"2, 4, 8, 24") are turned round (rising ↔ falling) rather than shuffled, and other
number lists never land in sorted order; **26 questions stay exactly as they are**
because they depend on position — 16 with a catch-all option ("none", "both",
"neither", कोई नहीं, दोनों में), 9 with sorted numbers beside a word ("0, 1, 2,
undefined", "50–60 words … no limit"), and 1 whose explanation cites a letter. The
order inside a chapter comes from a SHA-256 hash of the chapter id (no random module),
so it is the same on every Python version, and the result depends only on the
questions: a second run changes nothing. An independent check against the original
1,197 non-filler MCQs on `f31fa3e` confirmed that the correct option, option set, stem
and explanation (apart from the key letter) are unchanged; 849 keys moved and each of
the 30 lists turned round had been sorted. The 300 old filler MCQs are deliberately
replaced in place, bringing the bank to 1,497 real practice questions.
`tests/test_balance_mcq.py` pins the bands (overall 23–27%, per subject 20–30%, per
chapter at most ⌈n/4⌉ + 2 of one letter, no run of three), the script's rules, and an
end-to-end run on a throwaway bank; run against the original lopsided content, five of
its tests fail. After adding or editing MCQs: `python3 scripts/balance_mcq.py`.

**Found on the way.** Two English answers (chapters 22 and 23) held a list inside the
answer list, and the site printed it as a Python list, brackets and quotes included;

**Guard rails** (`tests/test_content_quality.py`): all completed English, Hindi and

## The new feature — direct downloads

*Request:* "direct download prev-year question and question bank". The repository
held no previous-year questions at all (only prose trend notes), so the feature
links CBSE's own files and also makes this hub's bank downloadable.

- **Official files** (`site/content/downloads.json`, rendered by `site/downloads.py`):
  per subject and course, the Class X board papers for ten sittings: 2026 and its
  second board exam, plus 2025, 2024, 2023 and 2022, each with its compartment
  sitting. Sample papers and marking schemes cover seven sessions: 2026–27 through
  2022–23, plus both terms of 2021–22. The manifest also links CBSE's question-bank
  and competency materials (Maths, Science, English) and additional practice
  questions for six subjects. In all, there are **271 file entries (270 distinct
  file URLs — one 2026 Maths ZIP serves both courses) plus 10 CBSE listing-page
  entries**. CBSE's names are irregular (`Hindi_Course_A_UPD.zip`, `Mathmatics_Std.zip`,
  one ZIP for Basic *and* Standard in 2026), so they cannot be generated from a
  pattern — hence a data file. Computer Applications has no 2026 second-exam paper
  and IT is a skill subject with its own sample-paper pages; both are shown as CBSE
  lists them.
- **Policy enforced on every build:** https only; host must be `www.cbse.gov.in` or
  `cbseacademic.nic.in`; `.pdf`/`.zip` only; every subject covered; sittings and
  sessions known. `tests/test_downloads.py` also pins CBSE's directory scheme so a
  paper cannot be filed under the wrong year. External links open in a new tab with
  `rel="noopener noreferrer"`.
- **Not re-hosted**, on purpose: they are CBSE's files, `.gitignore` excludes
  `*.pdf`/`*.zip` repo-wide (a copy would silently not ship), and one ZIP is 58.9 MB.
- **This hub's own bank:** 183 UTF-8 `.txt` files (3.9 MB raw, 0.9 MB gzipped) — one per
  subject and per chapter — and a Save-as-PDF path (`print.js` + print stylesheet)
  with answers or questions only, whole bank or one chapter. Plain text rather than
  PDF/DOCX because a stdlib PDF cannot shape Devanagari and a compressed `.docx` is
  not byte-stable across zlib builds, which would break the `docs/` drift gate.
- **Honesty:** a printed page keeps the footer's "not official CBSE papers" line and
  the credit (print hides only the link lists); official links are labelled as CBSE's,
  with the date they were last checked.
- Tests: **200 in the final PR** (103 at the start of the audit; 164 after the download/markup tests; the answer-key and content-quality coverage brought the final suite to 200).
